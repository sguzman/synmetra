# 📋 Experimental dependency SBOM and native runtime inventory

Synmetra's experimental Linux artifact workflow creates two machine-readable files, generated from its exact `Cargo.lock`, pinned source commit and compiled x86-64 default-feature binary. These files do **not** declare a stable release or certify complete Google Analytics parity.

| Artifact | Format | Source and scope |
| --- | --- | --- |
| `synmetra-rust-sbom.cdx.json` | CycloneDX 1.5 JSON | `cargo +1.99.1 metadata --locked --all-features`, including optional Rust DuckDB bindings and transitive Rust crates |
| `synmetra-native-runtime.json` | Versioned Synmetra JSON schema | GNU `ldd` loader-visible library names for the **default-feature** x86-64 release executable, plus the SHA-256 of that exact binary |

Both are generated by [ci/generate-sbom.sh](../ci/generate-sbom.sh), validated by `jq`, and included in the [experimental GitHub Actions release artifact](../.github/workflows/linux-release.yml) with the tarball and checksum. The SBOM uses package URLs (`pkg:cargo/name@version`) instead of private or runner-specific Cargo cache paths; Rust package licenses are recorded as **declared metadata**, never inferred legal clearance.

## Precise coverage boundary

- The CycloneDX inventory includes **all-feature resolved Rust packages**, not just the default set linked into the distributed binary. It does not mean that all optional features or their native C++ engines are shipped in that default executable.
- The loader inventory describes **direct/transitive native shared objects observed on the Ubuntu CI runner**. It is not a complete inventory of static libraries, code bundled into a binary, linker scripts, kernel/vDSO behavior or system packages on EndeavourOS. A successful build cannot guarantee another distribution carries the same runtime libraries.
- Rust declared license expressions are audited separately by [cargo-deny](DEPENDENCY_AUDIT.md). The native DuckDB C/C++ implementation, system glibc/libgcc and any redistributed third-party native code require their **own license notice and redistribution review**. Neither the SBOM nor `ldd` provides that legal determination.
- The generated files must be checked for correct source SHA, nonempty component/dependency lists, no leaked absolute workspace path, and no unresolved native shared object before the artifact is accepted.
- The archive's signed GitHub artifact provenance (once independently verified) binds its checksum to a GitHub workflow identity. It does not replace SBOM validation, native license review, binary signing, vulnerability assessment or the unaccepted stable release gates.

To generate the same type of evidence from a source checkout on Linux after building a default release binary, without Python, npm, Node or gcloud:

```fish
cargo +1.99.1 build --release --locked --bin synmetra
bash ci/generate-sbom.sh target/release/synmetra dist
jq '.components | length' dist/synmetra-rust-sbom.cdx.json
jq '.native_libraries' dist/synmetra-native-runtime.json
```

The values are environment- and source-specific. Reproducible SBOM output for the same locked dependency graph is distinct from independently reproducible native binary bytes; see [RELEASE_POLICY.md](RELEASE_POLICY.md) and the [acceptance ledger](progress.json).

The workflow verified the checksum, extracted the executable, performed isolated CLI smoke, validated at least 100 Rust components and dependency edges, and checked the default-feature ELF linkage for missing shared objects. The artifact is **not** a durable GitHub Release or a feature-enabled DuckDB binary.

The same run passed an independent locked release-build byte comparison and generated a short-lived GitHub/Sigstore SLSA v1 provenance attestation for the archive; [attestation 60004515](https://github.com/sguzman/synmetra/attestations/60004515) was verified with `gh attestation verify -R sguzman/synmetra` against the repository identity. Existing [cargo-deny evidence](DEPENDENCY_AUDIT.md) covers declared Rust licenses and advisory scans but does **not** complete the legal review of the bundled native DuckDB engine, dynamically linked system libraries, or redistributable native license notices. T216 therefore earns only its reviewable-output gate; native dependency/license clearance stays open.
